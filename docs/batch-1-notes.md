1. 先在正式页面导出备份，勿清除正式站点数据。在独立测试端口运行本分支静态服务器。
   用全新浏览器配置或无痕窗口访问，完成初始提示。
   确认普通模式仅有指挥台、舰队两个 tab；点击可回收，舰队建筑可以正常购买。
   在 1280×900 和 375×812 视口检查首屏核心决策不超过三项；新手航路与下一个目标不折叠。
2. 在测试地址导入 v31 备份，确认正常加载。记录导入前后建筑、研究、星核与碎片；
   星尘需扣除正常离线收益和在线生产影响。原档没有新字段时开关应关闭。
   分别测试原 activePage 为星港、星雨、委托的档案，普通模式回到指挥台。
3. 设置 → 显示全部系统：状态变为“当前：全部”；已解锁的星港、星雨、委托均可进入。
   未解锁或原规则不允许访问的系统仍不可进入。刷新后开关状态应保留。
   停在星港再关闭开关，应回指挥台，内容不丢失；再次开启应能重新进入。
   对新手和成熟档分别测试 compact 的两种值，开关开启时都显示全部已解锁 tab。
4. 逐个展开八类指定模块，检查按钮、列表和内容；刷新后默认折叠。

## 边界与剩余风险

- 核心层配置不强制解锁研究；这是保留原解锁规则和新手限制的结果。
- “仅核心”是用户指定的状态文案；成熟玩家仍遵循原中后期导航规则，并非永远只有三个 tab。
- 游戏逻辑、后台生产、离线结算仍运行；隐藏系统的进度不会暂停。
- 原任务建议与活动弹窗的触发逻辑未重构；某些后期建议可能指向被隐藏的入口，需设置开关访问。
- CSS 使用 :has 来避免未解锁折叠壳显示，旧浏览器兼容性未验收。
- GitHub Pages 工作流目前只对 main 推送或手动触发；草稿分支不会自动跑部署流水线。
- 旧 usability 断言会阻止部署测试通过；需先确认是否另行允许更新这一条测试，或改变目标显示要求。
