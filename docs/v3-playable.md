# v3「拾荒航线」试玩与验证

v3 是基于 PR #10 的独立可试玩重做分支。原生 HTML/CSS/JavaScript，无框架、无构建步骤。入口为 `/v3/`，旧版设置中也有试玩链接。默认旧版与旧版云存档继续保留；本 PR 保持草稿，不自动合并或部署。

## 已实现的循环

- 4 类生产设施；10、25、50 艘里程碑翻倍；5 项本轮研究；1/最多 10/最大批量购买及真实费用预览。
- 每航次一次主路线选择：工业强调设施协同与离线生产；回收强调扫描和信标爆发；探索缩短航程、减少产量分流、提高样本和风险成功率。
- 4 条探索航线。安全探索没有存量资源损失；风险探索明确显示成功率，失败仍保留 1 份样本。结果在派遣时写入存档，刷新不会重抽。
- 医院船和失落温室各有 3 个叙事选择。一次性故事、样本和永久舰装实际结算，最多 2 次故事选择/航次。舰装最多 3 级、2 个装备槽位。
- 第 1/2/3/4 次跃迁分别解锁自动购买、预算与优先级、自动研究、重复安全派遣。故事由玩家选择，自动化不会代选；未结算的探索会阻止跃迁。
- 3 阶段归航星港修复。花费可用星核不会减少历史星核的生产加成；修复、样本、舰装与故事跨跃迁保留。
- 每秒一个规则步长，支持毫秒余量和最多 8 小时离线结算。同一状态拆分推进或一次推进，生产、自动化和探索结果一致。
- 可导出、导入、恢复备份。损坏或未来版本记录暂停自动保存，另一窗口更新记录也暂停覆盖。弹窗支持 Tab 循环、Escape、焦点恢复与减弱动画偏好。

## 数值模拟结果

这些是确定性玩家模型结果，不是所有玩家的实际用时预测。模型：前 30 秒每秒扫描一次，每 15 秒回来一次，优先研究、随后最多购买 10 艘，捕获仍可见的信标，手动处理第一段探索故事；回收航线额外每 5 秒扫描。

| 航线 | 首艘无人机 | 10 艘里程碑 | 首段故事   | 首轮跃迁    | 第二轮跃迁  |
| ---- | ---------- | ----------- | ---------- | ----------- | ----------- |
| 工业 | 15 秒      | 2 分 15 秒  | 3 分 30 秒 | 18 分 53 秒 | 11 分 46 秒 |
| 回收 | 15 秒      | 1 分 30 秒  | 2 分 30 秒 | 19 分 45 秒 | 13 分 30 秒 |
| 探索 | 15 秒      | 2 分 15 秒  | 3 分       | 18 分 45 秒 | 12 分 45 秒 |

同一探索模型跑完 4 航次并依次修复星港，用时 53 分钟，永久能力全部解锁。模拟会断言首轮 15–25 分钟、第二轮至少快 20%、前 10 分钟发生研究/里程碑/故事变化，且 60 分钟内可完成星港。

## 存档兼容性

旧版 `SAVE_VERSION=31` 与键 `stellarOutpostIdleSave_v1` 保持可用。v3 使用版本 32、独立键 `stellarOutpostIdleSave_v3`，不会写入旧版主存档，也不接入旧版 Firebase 云端桥接。

玩家选择继承旧航站时，接入星尘、星核、跃迁次数与匹配的 4 类设施；不匹配的研究、其他建筑、正在进行的远征、未领取赛季奖励等所有原字段完整保存在 `legacyArchive`。旧档原文另存到 `stellarOutpostIdleSave_v31_backup_before_v3`，首次备份不会被后续导入覆盖；原版入口仍可以继续处理这些系统。v3 规则重做，不声称旧版与 v3 的产量或玩法等价。

恢复/重新启航前，当前 v3 原文先备份到 `stellarOutpostIdleSave_v3_before_restore`。备份或写入失败会中止恢复，当前记录保留。未经用户选择，旧记录不会自动迁入。

验证用的是包含不识别研究、额外建筑、活动远征和未领取奖励的构造旧档。尚未取得玩家的真实旧档，因此不宣称真实旧档已验收。

## 结构与视觉

| 文件                             | 职责                                               |
| -------------------------------- | -------------------------------------------------- |
| `v3/data.js`                     | 设施、路线、研究、探索、舰装、叙事与修复配置       |
| `v3/engine.js`                   | 无 DOM/存储依赖的规则、时间推进、迁移与边界处理    |
| `v3/storage.js`                  | 独立存档、原文备份、恢复与失败保护                 |
| `v3/app.js`                      | 页面、操作绑定、渐进导航、数值更新、弹窗与导入导出 |
| `v3/index.html` / `v3/style.css` | 原生页面和桌面/手机布局                            |

视觉使用生成的完整界面概念作为参考，并独立生成生产场景图。设计锁定近黑底 `#080f15`、板面 `#142029`、琥珀动作 `#edbb75`、青绿进度 `#7ed6c1`、4px 控件圆角；横向资源栏、左导航、开阔场景与右目标栏，设施与探索采用分隔行。手机先展示目标再显示场景。新存档首屏 3 个可点击控件、2 个可见导航项；初始舰队入口由“下一个目标”提供，避免重复按钮。

生产美术为 `v3/assets/salvage-orbit.webp`，使用内置 Image Gen。提示词主旨：橙色工业拾荒拖船、右侧破损环形轨道站、左下青色行星弧、近黑星空与残骸；保留暗色左上文字区；移除界面、按钮、字母、标识和水印。所有文案、资源数值、按钮和进度均为原生代码。场景经过 WebP 压缩；不需要外部字体或第三方 CDN。

## 浏览器验证

Browser 插件未配置，使用 Playwright + Chromium 153，中文字体为 Noto Sans CJK SC。HTTP 服务与浏览器在同一测试进程启动，避免独立命令之间的网络隔离。每个场景检查页面身份、非空内容、资源请求、运行时异常与控制台错误。

已验证：1280×900 和 375×900 的首屏、目标非空/无 hidden 祖先/offsetParent 可见、无横向滚动、扫描与被动产量、批量操作与路线选择、金色信标、安全/风险派遣、探索途中刷新、一次性故事与装备、跃迁保留、自动购买、预算与研究开关、星港修复、新航线开放、旧档导入与导出、损坏档保护、弹窗键盘、导入日志转义、大数显示。

还修复旧版“显示全部系统”对已归档星愿的可达性，以及 Space 快捷键吞掉 summary/select/链接的原生操作；回归夹具通过专家入口测试归档系统，并按真实 UI 展开折叠内容。旧版 usability、browser-smoke、mobile-performance、save-migration-v200、linked-journey-browser 已在 Chromium 实际通过；原数值、留存、路线/Build、联动、伴星故事和赛季测试也通过。

node tests/v3-gameplay.test.js
node tests/v3-balance.test.js

node tests/retention-flow.test.js

# 需要一个可用的 Playwright 模块和 Chromium 安装；不属于游戏运行依赖。
CODEX_PLAYWRIGHT_PATH=/path/to/playwright \
CODEX_CHROMIUM_PATH=/path/to/chromium \
node tests/v3-browser.test.js

CODEX_PLAYWRIGHT_PATH=/path/to/playwright \
CODEX_CHROMIUM_PATH=/path/to/chromium \
node tests/usability-flow.test.js

所有测试夹具使用隔离的浏览器 context，不清除真实玩家 localStorage。没有 `tests/game-math.test.js`，该仓库数值回归入口是 `tests/numeric-balance.test.js`。

发布前仍需用玩家真实旧档人工验收；PR 保持草稿。切换回旧版只需打开根路径 `/`，不需要删除任何记录。合并后的 GitHub Pages 部署与线上游戏尚未执行。
