2026-11-10用户已授权连续实施并上线；实施与真实验证进度见[v321-v324-validation](v321-v324-validation.md)。下文保留规划时的设计与审计依据。

本文件是 v3.20 发布任务中的只读审计及下一轮建议，**没有实施新玩法**。审计对象为 PR #18 的 `d2fc83cda98d0162ba585d9027d724ceae8458e1`，版本仍为 `3.20.0-preview.1`。以下工期顺序是依赖顺序，不是发布承诺。

## 当前证据与优先级

| 观察 | 代码或验证证据 | 对游玩的影响与判断 |
| --- | --- | --- |
| 远航重复操作集中 | `engine.js` 的 `startVoyage`、`dispatchVoyageLeg`、`claimVoyageLeg`、`finishVoyage`；三条路线均四段，首航和重访均需开始、四次派遣、四次领取、最终入库，共十次确认 | 阶段取舍有实际作用；重复路线也要求相同操作数量。优先减少已经明确安排的操作，保留新决定。 |
| 图谱完成后停止成长 | `surveyPreview` 在链内三节点归档后拒绝继续调查；三链合计九节点，完成后主要用于解锁远航及提供初始证据 | 不宜仅重置九个节点让玩家再做一次。需要具有不同证据目标的有限复查。 |
| 港务方向已有真实差异 | `harborTerms` 固定接单条款；生产方向支出抵工作量，接待实际预装缩短准备，探索增加可用航线；五项工程各三期 | 现有策略不是纯文案。下一步应改善比较和目标联动，先测量后调数值；不重算旧合同。 |
| 长期收藏有限 | 远航有十三件纪念、三份首航档案、十二条近期记录和个人最快航行；五工程最多十五期 | 不需要无限倍率。适合有限规划挑战、居民生活与设施用途的后续目标。 |
| 手机多系统共用探索页 | `app.js` 的 `longVoyages`、`sectorAtlas`、`harborPanel` 及 `style.css` 响应式；现有测试覆盖375宽、焦点及DOM连续性 | 无横向溢出不代表操作负担低。需新增任务点击数、滚动次数和触达路径测量，不能宣称已完成用户研究。 |
| 尚无唯一最优配装的充分证据 | 远航显式使用导航缩时、扫描回收、路线指定调查舰装；双槽和派遣快照已存在。已有经济模型验证可达与有限收益 | 需按生产水平、路线、目标和时间口径枚举合法配装，比较样本净收益、资源净收益、时间与分流；源码观察不足以认定万能配置。 |
| 自动化保留玩家决定 | 自动安全探索与故事分离；开始调查/远航停重复派遣；离线只完成当前阶段，不代领或选择后续 | 新便利应为玩家先安排的有限计划执行，遇新故事、缺资源、状态冲突停止。不能自动消耗未授权样本或替玩家决定剧情。 |

本次兼容与浏览器结果在 [v3.20 发布验收](v320-release-validation.md) 独立记录。真实玩家行为、长期留存和真实iPhone手感尚无数据，下面的体验判断明确属于代码与自动化流程审计。

发布审计另执行`node docs/validation/v320-release/strategy-audit.cjs`，退出0：[结果](validation/v320-release/strategy-audit.json)。三份原引擎正常赚取的结局档各实际付费完成九节点后，枚举已有三件舰装（扫描3级/医疗1级/导航2级）的七种合法空/单/双槽，得到153份可出航的首段预览及63份港务方向/需求条款。每份档在九组路线/方法中有七组的时间、分流、星尘净收益、样本净收益前沿只剩扫描＋导航；通信航线调查需要医疗，仍有收益/时间取舍。因此优先关注常规长航配置收敛，不能宣称所有舰装已均衡。此模型未覆盖尚未拥有的储能/生态装备、全部等级、后续阶段与港内生产机会成本，也不证明全游戏唯一最优或存在无限收益。下一轮平衡矩阵应补全这些维度，发布任务保持现有数值。

## v3.21：远航安排与手机归航处理

**实际功能建议**：首航继续逐段决定；已经完成的路线允许保存一份四段航行安排，在出发前逐段比较费用、双槽编成、预计航时、样本净变化和最坏资源缺口。玩家选择手动执行或明确授权一次性按安排接续；不循环自启。提供“领取本段并执行已确认下一段”的一次操作与“本次归航后暂停”。后台仍遵守最多八小时结算，首次实现只推进当前段，不跨段离线派遣。新的剧情/事件、缺费、非法或变化的编成、其他任务冲突均中止并说明。最终归航合并展示报告与入库，永久奖励依旧单次。手机归航待办允许在原页完成已经就绪的普通领取，保留重要确认。

**主要文件**：`v3/data.js` 安排说明；`engine.js` 计划校验和原子接续；`storage.js` 可选计划迁移；`app.js` 逐段比较/暂停/就绪待办；`style.css` 手机就地操作；`tests/v3-expansion.test.js`、`v3-browser.test.js`、兼容夹具。

**风险**：重复消费、代选、离线跨段超发、玩家换装使旧预览失效、合并操作丢焦点。先检查下一段全部条件，再原子结算；保存token、阶段及有限授权，重要选择不得默认勾选。不能为减少点击删掉费用确认。

**测试要求**：三路线×三结局、四段所有三类方法；刷新/导入/双窗口/过期token/连续双击；样本不足与冲突暂停；手动与按安排执行同样输入产生相同结算；八小时边界；旧活动航段原样接续；两种屏宽和双引擎键盘/焦点/DOM连续性。

**验收标准**：重复四段的正常路线完成所需真实确认由十次降到至多六次（计划保存单独计），首次剧情决定不减少；每笔费用和奖励可核对、重复执行无增益；375宽就绪操作无需反复打开不同折叠区；旧首航档案和永久结局逐字段保留。

## v3.22：星区证据复查与有意义的重访

**实际功能建议**：保留九节点首轮记录，完成一条链后开放该链三项有限复查议题。每项使用已有十二类事件证据与不同调查方法，揭示一个有来源的航路档案或居民回信；根据缺少的证据说明推荐航线和装备。复查成果提供后续远航的可选任务信息和有限出航便利，在航前明确选择，不永久叠乘产量。未发现证据可逐步探索，提供确定性安全获取路径，避免纯随机卡进度。已完成复查可回看和无奖励演练，普通回收仍可靠。

**主要文件**：`data.js` 数据驱动议题/证据映射；`engine.js` 有界进度、确定性掉落及一次结算；`storage.js` 可选复查记录；`app.js` 图谱节点详情/缺口直达；`style.css` SVG手机命中区；扩展、兼容、经济与浏览器测试。

**风险**：刷新重抽、首轮节点被覆盖、随机门槛、强迫刷同一事件、复查奖励通胀。新命名空间区分首轮与复查；派遣时锁定结果和来源；档案/便利数量封顶，无过期或连续签到。

**测试要求**：三链全部议题与所有证据路径；无证据档仍可达；刷新/离线/导入结果不重抽；每条奖励只能领一次；复查在途与旧调查/远航互斥；375宽SVG键盘和触屏点击；全套累积回归。

**验收标准**：九项复查均有不同的证据目标和实际记录；每项能从现有系统完成，最坏获取次数有上限并可解释；首轮九节点、远航解锁及旧收藏不变；完成后可完整回看，无无限刷样本或倍率。

## v3.23：居民生活与港务协作目标

**实际功能建议**：围绕现有获救居民增加三组、每组三段的生活后续，例如补给轮班、维修学徒、通信回信；按三个正式结局写相符的文字与设施状态。现有七类需求和五项有限工程联动解锁，交付仍用星尘、样本与已有探索，不新设货币。增加当前一项居民协作目标和两种可切换完成方式，让生产、接待、探索方向均可推进。完成后改变SVG居民活动、生活区或运输状态并获得有限纪念，已故人物仅通过历史/纪念内容出现。接单前用实际资源与等待比较三方向，不改已接合同。

**主要文件**：`data.js` 居民段落/条件/方案；`engine.js` 目标规则与港务派生模型；`storage.js` 可选后续记录；`app.js` 居民/星港详情及方向比较；`style.css` 减少动态效果；三结局兼容及浏览器测试。

**风险**：覆盖永久结局、复活已故人物、玩家以为切方向能改合同、一次奖励重发、三方向实际上同效。复用既有人物事实与固定合同，只给未来任务变化；用真实经济模型测量策略差异。

**测试要求**：三正式结局×三方向、三组全部九段；用v3.16/v3.20规范旧档进入，不重做主线；纯挂机路径、探索路径、离线、重复交付、工程满级、无样本档；SVG状态/剧情一致、减少动态效果与两种布局；旧经济全量保留。

**验收标准**：九段有真实解锁与交付，不是占位文字；每组至少两种可行规划路径，图景变化来自保存状态；三结局不改写且无奖励重发；生产、接待、探索至少各有一个在相应资源/在线条件下更合适的任务选择，并公开比较依据。

## v3.24：有限长期目标、平衡与版本收口

**实际功能建议**：新增十二项有限航海/港务成就（精打细算、补给保障、证据收藏、居民协作各三项），奖励档案、纪念和可视化陈列，避免永久倍率。提供一次归航的资源来源/支出、样本净变化、实际等待和下一目标的总结；加入按目标比较的两套已存装备和三方向建议，不自动替换。完成全路线目标后仍可按自己的纪录重复挑战，没有每日失效或无限赛季货币。先做经济审计，再仅调整被证明失衡的新数值。

**主要文件**：`data.js` 有限目标/文案；`engine.js` 有界达成判定、来源统计与比较；`storage.js` 幂等迁移；`app.js` 陈列/总结/建议解释；`style.css` 手机密度；经济模拟、扩展、兼容和完整浏览器测试；README、交接及验收文档。

**风险**：回溯不存在的历史、误发旧奖励、统计变相存无限日志、按单指标产生万能推荐、资源膨胀。旧档只承认可证明的永久记录，不能补造过去单次航行；统计有界，货币奖不无限；收益/时间/分流分别展示。枚举所有合法双槽及等级，在早/中/通关生产水平测试，不凭单一样本调平衡。

**测试要求**：十二项目标正反例/重复领奖/数值边界；v3.16→v3.24及每个中间版本活动状态迁移；三路线×合法配装×港务方向的收益、样本与时间前沿；长时间拆分/一次推进一致；全套`node scripts/check.cjs`和Playwright1.55.0 Chromium/WebKit；公开站点1280×900/375×900真实点击与性能记录；真实iPhone独立标记，不能由WebKit冒充。

**验收标准**：十二项目标均可操作达成，有清晰缺口与直达入口；不存在对所有路线、所有目标均严格占优的同一配装，若出现须有复现矩阵并调整；重复挑战不产生无限永久倍率或重复首航奖励；有限记录不随长期游玩无界增长；新旧存档、八小时离线、焦点/DOM/移动布局全部回归通过。

## 下一轮共同边界

维持原生HTML/CSS/JavaScript、双装备槽、独立v2/v3存储及schema32兼容策略（是否升schema由具体数据需求论证）。每版先规则与迁移，再真实交互，再累积回归后里程碑提交；保留原始失败。正式结局和首航档案不可覆盖。新功能只在下一轮明确授权后施工；本次发布不实施以上内容，不变更生产Firebase或部署规则。
